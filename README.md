# programmers-tracker

프로그래머스 풀이 과정을 **제출 단위로 빠짐없이 기록**하고, MCP 로 노출해
어떤 AI 로든 약점 진단·문제 추천·복습 관리를 받는 로컬 서버.

> ⚠️ 개발 중. 설계와 프로토콜 규명은 완료됐고 구현이 진행 중이다.

---

## 왜 만드는가

프로그래머스는 채점 결과를 그 순간에 흘려보내고 끝낸다. **지나간 제출을 조회할 API 가 없다.**
남는 것은 "풀었다/못 풀었다"와 날짜별 시도 횟수뿐이다.

실제 계정 기록이 이렇다.

```
2025년   총 시도 449회   푼 문제 43개
```

**449번 중 43번의 성공만 알 수 있고, 나머지 406번이 왜 실패했는지는 이미 소실됐다.**
BaekjoonHub 같은 기존 도구도 정답일 때만 동작해서 구조적으로 실패를 기록할 수 없다.

학습 신호는 실패에 있는데 기록은 성공만 남는다. 그 격차를 메운다.

---

## 어떻게 동작하는가

```
프로그래머스 웹          ← 탐색·검색·작성·실행·제출은 그대로 여기서
    │
    ├─ 센서 확장 ──────▶ "지금 이 문제 보고 있다" 신호만
    │
    └─ ActionCable ───▶ 서버가 같은 채널을 구독 → 결과가 브로드캐스트로 유입
                              │
                              ├─ verdict 판별 · 시도 간 diff 생성
                              ├─ ps-records/ 에 기록 + git 커밋
                              └─ MCP 노출 ──▶ Claude · Cursor · 로컬 LLM
```

**서버는 프로그래머스에 아무것도 보내지 않는다.** 같은 채널을 구독해 듣기만 하고,
코드는 문제 페이지에서 가져온다. 제출은 사용자가 브라우저에서 직접 한다.

프로그래머스의 채점은 REST 가 아니라 **Rails ActionCable WebSocket** 이며,
같은 채널을 구독한 모든 클라이언트가 동일한 메시지를 받는다는 점을 이용한다.
프로토콜 규명 전말은 [`docs/programmers-protocol.md`](docs/programmers-protocol.md).

## 기존 도구와 무엇이 다른가

| | BaekjoonHub | programmers-tracker |
|---|---|---|
| 기록 시점 | 정답일 때만 | **모든 `run` · `submit`** |
| 실패 코드 | ✗ | ✅ |
| 시도 횟수 · 소요 시간 | ✗ | ✅ |
| 실패 유형 구분 | ✗ | ✅ 오답 / 시간초과 / 런타임 / 컴파일 |
| 테스트케이스별 결과 | DOM 스크래핑 | **원본 스트림** |
| 시도 간 diff | ✗ | ✅ |
| AI 분석 | ✗ | ✅ MCP |

---

## 무엇을 알 수 있게 되는가

- 주로 **어떻게** 죽는가 — 논리 오류인가, 시간초과인가, 단순 실수인가
- **첫 제출 통과율** — 실전에서 가장 중요한 지표
- 유형별 약점 (solved.ac 태그 180종 기준)
- **통과했지만 느린 문제** — 출제 의도를 비켜간 풀이
- 반복하는 실수 — AI 가 시도 간 diff 를 읽고 짚어낸다
- 복습 시점 — 확신도 기반 간격 반복
- 기업별 출제 성향 — 카카오 기출 98문제를 태그로 집계

```
programmers-tracker/            (이 저장소)
├── CLAUDE.md                   개발 헌법 — 금지·품질 게이트·state 운영
├── .claude/commands/           프로젝트 전용 위키 커맨드
├── .githooks/                  push 게이트 — 위키 기록 없는 push 차단
├── .harness/state/             세션 밖 기억 (goal · progress)
├── docs/
│   ├── programmers-protocol.md   프로토콜 리버스 엔지니어링 (실측 근거)
│   ├── development-rules.md      코딩 컨벤션
│   ├── llm-wiki/                 개발 과정 기록
│   └── superpowers/specs/        설계 문서
├── src/                        Kotlin + Spring Boot
└── template/ps-records/        기록 저장소 초기 구조

ps-records/                     (별도 저장소 — 서버가 생성)
```

> Claude Code 는 세션 시작 훅이 자동으로 설정한다.

## 프로그래머스에 대한 원칙

- 이 도구는 **개인 학습 기록용**이며 본인 계정에만 사용한다
- **자동 제출 기능을 제공하지 않는다.** 제출은 사용자가 브라우저에서 직접 하고,
  서버는 결과를 관찰해 기록할 뿐이다
- 서버가 보내는 요청은 채널 구독 · 문제 페이지 조회 · 카탈로그 조회뿐이며
  모두 브라우저가 하는 것과 같은 수준이다
- 카탈로그 폴링은 하루 1회를 넘기지 않는다
- 프로그래머스가 중단을 요청하면 따른다

비공개 프로토콜을 이용하는 도구이므로 사용에 따르는 판단과 책임은 사용자에게 있다.
