# programmers-tracker

**[English](README.md)**

프로그래머스 채점 스트림을 지켜보다가 **모든 `run` 과 모든 `submit` 을 — 실패까지 포함해서** —
직접 소유한 git 저장소에 기록하는 로컬 서버입니다.

> **상태: Phase 1, 진행 중.** 설계와 프로토콜 역공학은 끝났습니다. 수집 절반은 만들어졌고,
> **읽기 전용** 분석 절반도 만들어졌습니다. 설계에서 남은 것은 서버가 필요 없거나, AI에게 쓰기를
> 허용할지에 대한 결정이 필요합니다.
> **[지금 동작하는 것](#지금-동작하는-것)이 이 문서에서 구현 상태를 말하는 유일한 절입니다.**
> 그 뒤는 전부 설계 설명이고, 어느 부분이 실재하는지는 그 표가 말합니다.

---

## 왜 만들었나

프로그래머스는 채점 결과를 그 순간에만 흘려보내고 놓아버립니다. **지난 제출을 조회할 API가
없습니다.** 남는 것은 "풀었다 / 못 풀었다" 와 날짜별 시도 횟수뿐입니다.

실제 계정 기록은 이렇게 생겼습니다:

```
2025   총 시도 449   푼 문제 43
```

**449번의 시도 중 알 수 있는 것은 성공한 43번뿐이고, 나머지 406번이 왜 틀렸는지는 이미
사라졌습니다.** BaekjoonHub 같은 기존 도구는 정답일 때만 동작하므로 구조적으로 실패를 기록할
수 없습니다.

배움의 신호는 실패에 있는데 기록에는 성공만 남습니다. 이 도구는 그 간극을 메웁니다.

## 지금 동작하는 것

지금 설치하면 얻는 것이 이것입니다. 절 번호는
[설계 문서](docs/superpowers/specs/2026-08-04-programmers-tracker-design.md)를 가리키며,
*설계됨* 으로 표시된 것은 `src/` 에 존재하지 않습니다.

| | 상태 |
|---|---|
| 지켜보는 문제의 모든 `run`·`submit` 을 채점 스트림에서 실시간 수집 | **구현됨** |
| 실측된 5가지 판정 — 통과 · 오답 · 시간 초과 · 런타임 에러 · 컴파일 에러 | **구현됨** |
| 분류하지 못한 채점은 이웃 값으로 밀어 넣지 않고 `UNKNOWN` 으로 남김 | **구현됨** |
| 테스트케이스별 결과, 시도 번호, 소요 시간 | **구현됨** |
| 원본 프레임을 기록 옆에 그대로 보존 | **구현됨** |
| 내 git 저장소에 기록 — 커밋하고, 합격 시 푸시하고, 매일 백업 | **구현됨** |
| 기록 저장소당 인스턴스 하나, 시작 시점에 강제 | **구현됨** (실측된 macOS 단서 — [`bootstrap.md`](docs/bootstrap.md)) |
| 지금 어느 문제를 푸는지 서버에 알리기 | **구현됨** — 문제마다 `curl` 하나, 또는 아래 센서 |
| 대신 알려주는 브라우저 센서 | **구현됨** — [`extension/`](extension/README.md), 압축 해제 상태로 로드; 2026-08-10 브라우저에서 검증 |
| 틀린 코드를 기록과 함께 저장 | **구현됨** |
| 문제별 페이지, 그리고 시도 간 diff | **구현됨** |
| 채점기가 준 예제로 만든 문제별 실행기 | **구현됨** — java · python3 · cpp · javascript · kotlin · c · csharp; 나머지는 이유를 대며 거부 |
| 카탈로그에서 가져온 문제 제목과 태그 | **구현됨** — 689문제, 내장 |
| MCP 서버 — Claude · Cursor · 로컬 LLM이 기록을 읽음 | **구현됨** — 읽기 툴 6개 ([`mcp.md`](docs/mcp.md)) |
| 복습 큐 — 내가 통과한 문제에 대한 간격 반복 | **구현됨** — `review_queue`, §6.4 |
| 통과했지만 느림 — 효율성 테스트라면 떨어졌을 통과 | **구현됨** — `slow_passes`, §6.5 |
| 태그별 약점 · 시험 모드 · 회사별 프로필 | 설계됨 · §6 |

이 표에서 한 가지는 따로 말해둘 값어치가 있습니다. 첫 한 시간의 경험을 바꾸기 때문입니다:
**서버가 모르는 문제에 제출하면 그 기록은 조용히 사라집니다.** 센서 확장을 로드하면 그 부담이
없어지지만, 확장은 브라우저 프로필마다 압축 해제 상태로 로드해야 하므로 로드되지 않은 환경에서는
두 필드짜리 `curl` 로 문제를 직접 등록해야 합니다.
[`docs/bootstrap.md`](docs/bootstrap.md) 가 그 간극 전체를 다룹니다.

## 시작하기

Docker, 프로그래머스 로그인, 그리고 기록을 담을 내 git 저장소가 필요합니다.

```bash
git clone https://github.com/BrokenFinger98/programmers-tracker.git
cd programmers-tracker

cp -R template/ps-records ~/ps-records && git -C ~/ps-records init   # 내 기록 — 내 것이고, 분리되어 있음
mkdir -p .ps && printf '%s' 'YOUR__session_production_COOKIE' > .ps/session

cp .env.example .env    # TRACKER_RECORD_REPO, GIT_AUTHOR_NAME, GIT_AUTHOR_EMAIL 설정
docker compose build && docker compose up -d   # 먼저 빌드: up 만 하면 낡은 이미지를 재사용합니다
```

**[→ 전체 안내: `docs/bootstrap.md`](docs/bootstrap.md)** — 쿠키를 어디서 찾는지, `/watch` 토큰이
어떻게 동작하는지, 제대로 설치된 상태가 어떤 모습인지. 꼭 읽으십시오. 위 다섯 줄만으로는 기록이
생기지 않습니다.

JDK 25 위에서 네이티브로도 돌아갑니다 (`./gradlew bootRun`). 안내서가 두 방식을 모두 다룹니다.

## 어떻게 동작하도록 설계되었나

```
프로그래머스 웹          ← 탐색 · 검색 · 작성 · 실행 · 제출은 전부 여기서
    │
    ├─ 센서 확장 ──────▶ "지금 이 문제를 보고 있다" 는 신호만
    │
    └─ ActionCable ───▶ 서버가 같은 채널을 구독 → 결과가 브로드캐스트로 도착
                              │
                              ├─ 판정 결정 · 시도 간 diff
                              ├─ ps-records/ 에 기록 + git 커밋
                              └─ MCP 노출 ──▶ Claude · Cursor · 로컬 LLM
```

이것이 설계 전체입니다. 이 중 무엇이 오늘 존재하는지는 위의 표가 말합니다.

**서버는 프로그래머스에 아무것도 보내지 않습니다.** 같은 채널을 구독해서 듣기만 합니다.
제출은 사용자가 브라우저에서 직접 합니다.

프로그래머스 채점은 REST가 아니라 **Rails ActionCable WebSocket** 이고, 같은 채널을 구독한 모든
클라이언트가 동일한 메시지를 받는다는 사실을 이용합니다.
프로토콜 전말: [`docs/programmers-protocol.md`](docs/programmers-protocol.md).

## 기존 도구와 무엇이 다른가

두 도구가 각각 무엇을 하도록 만들어졌는지입니다. 무엇이 구현되었는지는 위의 표가 authority입니다.

| | BaekjoonHub | programmers-tracker |
|---|---|---|
| 기록을 촉발하는 것 | 정답 제출 | 모든 `run` 과 모든 `submit` |
| 실패 | 기록되지 않음 — 구조적으로 불가능 | 이 도구의 존재 이유 |
| 데이터 출처 | 결과 페이지 스크래핑 | 채점 스트림 그 자체 |
| 테스트케이스별 상세 | 페이지가 렌더링한 것까지 | 모든 테스트케이스 프레임을 그대로 보존 |
| 실패 유형 | — | 오답 · 시간 초과 · 런타임 · 컴파일 |
| 시도 횟수 · 소요 시간 | — | 제출마다 기록 |
| 코드, diff, AI 분석 | — | 그 기록 위에 설계됨 |

---

## 이 기록이 무엇을 알려주도록 설계되었나

수집 형식은 아래 질문들에 답하기 위해 존재합니다. 설계 §6이고, 무엇이 구현되었는지는 위의 표가
추적합니다.

- **어떻게** 주로 죽는가 — 논리 오류인가, 시간 초과인가, 단순 실수인가
- **첫 제출 통과율** — 실전에서 가장 중요한 지표
- 유형별 약점 (solved.ac 태그 어휘 기준)
- **통과했지만 느린 문제** — 의도된 접근을 비껴간 풀이
- 반복되는 실수 — AI가 시도 간 diff를 읽고 짚어줌
- 언제 복습할지 — 확신도 기반 간격 반복
- 회사별 출제 경향 — 카카오 기출 98문제를 태그로 집계

## 구조

```
.                               (이 저장소)
├── CLAUDE.md                   개발 헌법 — 금지 사항 · 품질 게이트 · 상태 운영
├── Dockerfile                  멀티 스테이지 이미지 — JVM 25, 설정은 굽지 않음
├── compose.yaml                기록과 쿠키를 마운트; 루프백에만 공개
├── .env.example                .env 로 복사 — 기본값이 있을 수 없는 설정들
├── .claude/skills/             프로젝트 범위 스킬 (issue · commit · pull-request · wiki)
├── .githooks/                  푸시 게이트 — 헌법 가드, 그다음 위키 기록 확인
├── .harness/state/             세션 밖 기억 (goal · progress)
├── docs/
│   ├── bootstrap.md              설치 안내 — 실행하려면 여기부터
│   ├── programmers-protocol.md   프로토콜 역공학 (실측 증거)
│   ├── development-rules.md      코딩 규약
│   ├── llm-wiki/                 개발 과정 기록
│   └── superpowers/specs/        설계 문서
├── scripts/                    check · test · build · guards — CI가 같은 파일을 실행
├── src/                        Kotlin + Spring Boot
└── template/ps-records/        기록 저장소의 초기 구조
```

기록은 **직접 만드는 별도 저장소** 에 들어가고(위 *시작하기* 의 `cp -R template/ps-records …`),
서버는 그 안에 쓰기만 합니다. §5.5의 파생 페이지가 생기면 Obsidian 볼트로 열 수 있습니다.

> 클론 후 한 번: `git config core.hooksPath .githooks` — 푸시 게이트를 켭니다.
> 헌법 가드를 먼저 돌리고, 그다음 위키 기록을 요구합니다.
> Claude Code는 세션 시작 훅으로 자동 설정합니다.

## 프로그래머스를 대하는 원칙

- 이 도구는 **개인 학습 기록용** 이며 본인 계정에서만 사용합니다
- **자동 제출 기능이 없습니다.** 사용자가 브라우저에서 직접 제출하고, 서버는 결과를 관찰해
  기록할 뿐입니다
- 서버가 프로그래머스에 보내는 요청은 두 종류뿐이고, 둘 다 브라우저가 이미 하는 수준입니다:
  채널 구독, 그리고 작성한 코드를 회수하기 위한 문제 페이지 조회 (§4.4).
  **카탈로그는 절대 가져오지 않습니다** — 문제 제목·레벨·태그는 jar 안에 들어 있고, 설치마다
  한 번이 아니라 모두를 위해 한 번만 수집했습니다
  ([결정 문서](docs/llm-wiki/wiki/decisions/2026-08-06-shipped-problem-catalog.md))
- 프로그래머스가 중단을 요청하면 따릅니다

이 도구는 비공개 프로토콜을 사용하므로, 사용에 대한 판단과 책임은 사용자에게 있습니다.
