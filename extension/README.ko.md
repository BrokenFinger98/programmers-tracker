# 센서 확장

**[English](README.md)**

이 확장의 유일한 일(설계 §8): 로컬 서버에 **지금 어느 문제를 보고 있는지** 알리고, 브라우저만
볼 수 있는 두 가지를 보고하는 것. 네 개의 필드만 보냅니다 — 코드도, 결과도, 쿠키도 보내지
않으며, 프로그래머스에는 아무 요청도 하지 않습니다.

이것이 없으면 문제마다 DevTools와 `curl` 로 직접 등록해야 하고, 언어 탭을 바꿀 때마다 그리고
서버를 재시작할 때마다 반복해야 합니다. 설계된 도구와 실재하는 도구 사이의 가장 큰 간극이
이것이었습니다 (#97).

## 설치

Chrome 또는 Chromium 계열 브라우저에 압축 해제 상태로 — 스토어에 올라가 있지 않습니다:

1. `chrome://extensions` 를 열고 **개발자 모드** 를 켭니다
2. **압축해제된 확장 프로그램을 로드합니다** 로 이 `extension/` 디렉터리를 선택합니다
3. 확장의 **옵션** 을 열고(툴바 아이콘 → ⋮ → 옵션), **이 저장소 체크아웃의**
   `.ps/watch-token` 내용을 붙여넣습니다 — 기록 저장소가 아닙니다. 자격 증명이고 기록 저장소는
   푸시되기 때문입니다 (#126). `TRACKER_PORT` 를 바꿨다면 포트도 설정합니다

그다음 아무 프로그래머스 문제나 엽니다. 툴바 배지가 상태입니다:

| 배지 | 의미 |
|---|---|
| 초록 `●` | 감시 중 — 서버가 알림을 받았고, 이 문제에 대해 아직 기록된 것이 없습니다 |
| 초록 `✓` | 이 문제의 마지막 채점이 **기록되었습니다.** 판정이 무엇이든 상관없습니다 |
| 보라 `?` | 기록은 됐지만 서버가 분류하지 못했습니다 — `UNKNOWN` 또는 `INCOMPLETE` |
| 빨강 `!` | 서버는 살아 있는데 **이 문제가 관찰되고 있지 않습니다** — 마우스를 올리면 어느 자격 증명을 고쳐야 하는지 나옵니다 |
| 주황 `!` | 아직 토큰이 설정되지 않았습니다 |
| 빨강 `×` | 서버가 거부했거나 닿지 않았습니다. 마우스를 올리면 서버가 준 메시지가 보입니다 |
| 배지 없음 | 콘텐츠 스크립트가 아예 돌지 않았습니다 — 문제 페이지가 아니거나, 이 프로필에 확장이 로드되지 않았습니다 |

마우스를 올리면 상세가 보입니다: 판정, 테스트케이스 개수, 얼마나 전인지.

**기록된 오답도 `✓` 입니다.** 배지는 "내가 맞혔나"가 아니라 **"도구가 동작하나"** 에 답합니다.
실패를 기록하는 것이 이 도구가 할 일이고, 거기에 빨간 표시를 두면 자기 오답을 센서 고장으로
읽게 됩니다.

**`?` 가 멈춰 서야 할 신호입니다.** 서버가 분류하지 못한 기록을 썼다는 뜻이고, 채점이 유실될 때
바로 그 모양입니다. 2026-08-11에 통과한 제출이 `UNKNOWN` 으로 기록됐는데 화면의 어떤 것도 그와
어긋나 보이지 않았고, 그 유실은 20분 동안 조용했습니다 (#154). 이 배지가 그 "어긋남" 입니다.

**빨강 `!` 는 다른 모든 상태를 제칩니다.** `/watch` 는 구독이 살아 있든 아니든 `started` 를
답했고, 그래서 연결된 적 없는 채널도 배지는 초록, 하트비트는 매번 200이었습니다 (#167). 이제
서버가 소켓 자신의 판정을 보고하고, 닿지 않거나 거부된 채널은 그렇다고 말합니다 — 한 시간 전의
`✓` 는 사실이지만, 지금 아무것도 관찰되고 있지 않다면 무의미합니다.

⚠️ **하지만 만료된 세션 쿠키는 잡지 못하고, 현재 무엇도 잡지 못합니다.** 2026-08-11 실측
(#175, 프로토콜 §15.3): 인증되지 않은 구독도 **0.5초 만에 승인되고 정상적으로 ping 을 받으며**,
브로드캐스트만 오지 않습니다. 수동 관찰자가 가진 모든 생존 신호가 살아 있는 세션과 죽은 세션
사이에서 **동일합니다.** 그래서 배지는 초록인 채로 아무것도 기록되지 않습니다. 배지가 멀쩡해
보이는데 기록이 끊겼다면 `.ps/session` 을 교체하십시오 — 이 배지가 볼 수 없는 실패입니다.

좋은 상태를 포함해 모든 상태에 글리프가 있습니다. 예전에는 초록색에 텍스트가 없었는데, 배지
배경은 **텍스트 뒤에** 칠해지므로 아무것도 그려지지 않았고, 동작 중인 센서가 로드되지 않은 것과
똑같아 보였습니다 (#147). 이제 "배지 없음" 은 말 그대로의 뜻입니다.

상태는 하트비트로 오므로 채점보다 최대 30초 늦을 수 있습니다. 검증이 목적인 신호에는 충분하고,
스피너를 두지 않는 이유이기도 합니다 — 진행 표시를 하려면 페이지를 들여다봐야 하는데, 이 확장은
그것을 일부러 하지 않습니다.

## 무엇을 보내나

`POST /watch` 한 번, 네 개의 필드:

```json
{ "lessonId": "120803", "language": "java", "focusedSec": 612, "sawQuestions": false }
```

앞의 둘은 서버가 스스로 알아낼 수 없는 것입니다 (#114). 문제 번호는 URL에서 옵니다 — 문제의
하위 페이지를 포함해 항상 존재하는 유일한 곳입니다. 언어는 코드 편집기의 `data-language` 에서
오고, 이것만이 DOM이 필요한 부분입니다. 채널 식별자는 문제의 속성이므로 서버가 문제 페이지에서
직접 읽어 캐시합니다.

뒤의 둘은 서버가 **영원히** 알 수 없는 것입니다 (#120). `focusedSec` 은 이 탭이 보이면서
포커스를 가진 초만 셉니다. "이 문제에 얼마나 매달렸나"에 답하는 숫자가 이것입니다 — 기록의
`elapsedSec` 은 문제가 announce된 시점부터의 벽시계 시간이라, 저녁 먹기 전에 연 문제는 세 시간으로
찍힙니다. `sawQuestions` 는 막혀 있는 동안 질문하기 탭을 열었는지를 말합니다. 둘 다
`review_queue`(§6.4)가 씁니다.

편집기가 없는 페이지는 아무것도 알리지 않습니다. 질문 목록은 풀고 있는 문제가 아닙니다.

페이지를 열 때, 그 값들이 바뀔 때, 그리고 30초마다 보냅니다. 서버는 멱등합니다 — 같은 내용을
다시 보내면 `started` 가 아니라 `refreshed` 로 답합니다 — 이것이 서버 재시작 후 문제를 다시
등록해 주는 장치입니다.

## 왜 요청이 서비스 워커를 거치나

콘텐츠 스크립트의 교차 출처 `fetch` 는 페이지의 CORS 규칙을 따르는데, 로컬 서버는 CORS를
전혀 공개하지 않습니다 — 의도적입니다. 허용적인 CORS는 브라우저의 아무 페이지나 서버에 닿게
만들기 때문입니다. 그래서 `sensor.js` 는 DOM만 읽고 본문을 `background.js` 에 넘기며,
`background.js` 의 `host_permissions` 가 `127.0.0.1` 을 덮으므로 요청을 보낼 수 있습니다.

## 권한, 그리고 각각이 필요한 이유

| 권한 | 이유 |
|---|---|
| `storage` | watch 토큰과 포트를 기억 |
| `host_permissions: http://127.0.0.1/*` | 무언가를 보내는 유일한 곳 |
| `school.programmers.co.kr/learn/courses/*/lessons/*` 콘텐츠 스크립트 | 문제 번호와 열려 있는 언어 탭을 읽음 |

`tabs` 권한도, 방문 기록 접근도, 원격 코드도 없습니다.

## 무엇이 실측되었고 무엇이 아닌가

셀렉터들은 **살아 있는 문제 페이지에서 직접 읽었고**(120803번 문제, 2026-08-07), 언어 탭 전환이
언어만 바꾸고 문제 자체의 식별자는 그대로 둔다는 것도 실측했습니다. 2026-08-10에는 다시 쓴
리더를 살아 있는 세 페이지에 대고 돌렸습니다 — 문제 페이지, SQL 문제, 그리고 편집기가 없는
질문 페이지(올바르게 "아무것도 아님"으로 읽힘). 요청 계약도 실제로 도는 서버에 대고
확인했습니다: `started`, 반복 시 `refreshed`, 그리고 배지가 보여주는 오류 본문과 함께 `401`.

**로드해서 동작을 눈으로 확인, 2026-08-10.** Chrome, 압축 해제, 토큰 붙여넣기, 문제 페이지 열기:
배지가 초록으로 바뀌며 `watching lesson 181947 in java (refreshed)` 를 표시했고, 서버 로그에도
같은 빌드가 응답한 기록이 남았습니다. 매니페스트 배선, 서비스 워커 중계, 배지 — 쓰여 있기만 한
것이 아니라 증명되었습니다.

그 첫 시도가 잡아낸 것 하나는 알아둘 값어치가 있습니다: 배지가
`400 INVALID_REQUEST — challengeableId is missing` 를 표시했는데, 이는 현재 서버가 보지도 않는
필드입니다. 컨테이너가 나흘 묵은 것이었습니다. `docker compose up -d --build` 로 다시 올리고,
서버가 시작할 때 찍는 `Running build …` 줄을 확인하십시오.
