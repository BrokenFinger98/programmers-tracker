# 코드 작성은 프로그래머스 웹 편집기에서

## 맥락
"자동완성 없이 직접 작성하고, 막히면 IDE 디버거를 쓰고 싶다"는 요구에서 출발해
초기에는 **로컬 편집기 + 서버 능동 제출**로 설계했다.

## 검토한 선택지
- **A. 로컬 편집기 중심** — 서버가 문제를 스캐폴딩하고 로컬 파일을 제출
- **B. 웹 편집기 중심** — 프로그래머스에서 그대로 풀고 서버는 관찰만

## 결정
**B.** 사용자는 프로그래머스 웹에서만 논다.

## 이유
A 는 **문제 탐색·검색·설명 읽기를 CLI 로 재구현**해야 하는데, 이는 프로그래머스가 이미
잘하는 것을 더 나쁘게 다시 만드는 일이다.

더 중요한 것은 **실전 코딩테스트가 웹 편집기에서 치러진다**는 점이다. 자동완성 없는
환경에 익숙해지는 것이 목적이었으므로 웹에서 푸는 쪽이 오히려 목적에 부합한다.

디버깅 요구는 서버가 캡처한 코드로 `Solution.java` + `SolutionTest.java` 러너를 생성해
해결한다. 웹에서 풀다 막히면 IntelliJ 로 열어 중단점을 찍으면 된다.

## 받아들인 비용
- 로컬에서 코드를 쓰는 경로는 부차적이 된다 (Judge 컴포넌트는 남아 있어 나중에 복원 가능)
- 캡처 타이밍이 사용자 행동에 종속된다
